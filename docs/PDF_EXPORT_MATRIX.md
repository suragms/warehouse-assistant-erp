## Installed implementation, not assumed libraries

`backend/PurchaseAssistant.Infrastructure/PurchaseAssistant.Infrastructure.csproj` installs SkiaSharp and Linux native assets 4.153.1. `Services/ExportFileBuilder.cs` uses SKDocument for PDF, hand-built ZIP/XML OpenXML for stock XLSX, its own UTF-8 CSV encoder, and framework ZipArchive/JSON. No QuestPDF, iText, PdfSharp, ClosedXML or EPPlus PackageReference found. `frontend/package.json` installs jsbarcode ^3.12.3 for labels; no jspdf, pdfmake, html2pdf or SheetJS dependency. Keep the working builders unless a measured requirement justifies a library change and license review.

`frontend/src/layouts/AppShell.tsx` is browser chrome. `public/manifest.webmanifest`, `public/sw.js` and `components/PwaUpdate.tsx` provide a PWA shell/offline notice; service worker bypasses `/api/`. No Electron/Tauri shell, native filesystem/IPC or desktop-specific save dialog exists. Browser Blob/download and clipboard are the actual desktop workflows. Browser print/Save PDF is a separate user-agent capability.

## Output acceptance

The 525 backend unit/endpoint tests passed in this audit, including export signatures, role-redaction/subset rules and spreadsheet package contents; 127 frontend tests and 56 selected mock browser tests passed. A `%PDF` prefix is not proof of complete content or a readable report. No server-generated PDF pages were visually rendered in this audit. Browser print screenshot was inspected; it shows the label only and proves no physical scanner/printer fidelity.

Before report release: extract/check text and totals from the full PDF, render and review all pages, verify font availability in Windows/Linux deployment, then exercise real authorized PostgreSQL-backed downloads. Keep document generation separate from backup recovery and from provider delivery.
